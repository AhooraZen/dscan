## Dependency notes
- **Plan 001 must be executed first**: It establishes unit tests and tempdir integration test suites so every subsequent bug fix and optimization is verifiable via `cargo test`.
- **Plans 002 through 006** resolve core correctness, memory safety, and concurrency bugs against the established test baseline.
- **Plan 009 depends on 006**: Safe `getdents64` buffer parsing bounds are required before passing entry names to `fstatat`.
- **Plan 010 depends on 009**: Eliminating per-entry `PathBuf` construction is enabled by resolving child entries via `fstatat(fd, ...)`.
- **Plan 011** is standalone and can be executed at any time to clean up git status.
- **Plan 012** should be run after code changes land or continuously during execution to keep `cargo clippy` and `cargo fmt` green.
- **Plan 013 depends on 001, 006, 008**: Implements the ultimate 50x performance architecture with kernel `statx` (`AT_STATX_DONT_SYNC`, `STATX_BLOCKS`), Chase-Lev lock-free work-stealing deques, 512 KiB page-aligned buffers, zero-allocation path stack, and cache-line padded atomics, elevating and superseding incremental optimizations in 009/010.

## Findings considered and rejected
- **Adding external dependencies (e.g. `clap`, `rayon`, `nix`)**: Rejected. The core design principle of `dscan` is zero external dependencies, fast compilation, and minimal binary size. All improvements stay strictly within Rust stdlib and raw POSIX/Linux syscalls.
- **Replacing TUI with a heavy terminal UI library (`ratatui`)**: Rejected. `dscan` is a lightweight, non-interactive CLI scanner that outputs results to stdout; heavy TUI frameworks complicate Unix pipeline integration.
