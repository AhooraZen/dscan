## Dependency notes
- **Plan 033** diagnoses the 10 core bottlenecks and benchmarks.
- **Plan 034 depends on 033**: Solves container CFS quota CPU freeze (`/sys/fs/cgroup/cpu.max`), standardizes AArch64 ABI layout on `sys_statx`, eliminates local recursion `PathBuf` heap allocations, provides flat subdirectory buffers, implements single-CAS atomic `steal_batch`, and adds Windows junction cycle tracking.
- **Plan 035 depends on 033, 034**: Eliminates the 171ms–800ms `HashMap<PathBuf, u64>` post-scan merge bottleneck with tree-to-tree `DirArena::merge_subtree` grafting and O(N) array rollup, modularizes monolithic `scanner.rs` into clean submodules, and strips dead `io_uring` setup overhead.
- **Plan 036 supersedes Plan 022 and depends on 032, 035**: Nukes fragile GPUI desktop implementation in `dscan-gui`, generalises `dscan-android` into cross-platform `dscan-jni`, and migrates desktop to Compose Multiplatform (Kotlin + Skia), sharing 100% of Compose UI across Android, Linux, Windows, and macOS.
- **Plan 037**: Unifies Cargo workspace dependency inheritance, adds Android Gradle wrapper, enables R8 release minification, configures workspace-wide CI matrix, and aligns documentation.

## Findings considered and rejected
- **Adding external dependencies (e.g. `clap`, `rayon`, `nix`)**: Rejected. The core design principle of `dscan` is zero external dependencies, fast compilation, and minimal binary size. All engine improvements stay strictly within Rust stdlib and raw POSIX/Linux/Windows syscalls.
- **Using `io_uring` for directory metadata batching**: Rejected based on empirical microbenchmarking showing `newfstatat`/`statx` is 2.91x faster than `io_uring` for cached filesystem entries in Linux VFS dcache.
- **Fixing GPUI desktop bugs incrementally**: Rejected. Migrating to Compose Multiplatform reuses the tested, fluid Android Compose UI across Linux/Windows/macOS, eliminating display-server bugs and toolchain fragility.
